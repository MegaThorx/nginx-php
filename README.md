# nginx-php

Docker images with **nginx and PHP-FPM** on Alpine Linux, run by supervisord, for every supported PHP version.
They are built on the official [`php:<version>-fpm-alpine`](https://hub.docker.com/_/php) images and rebuilt
automatically whenever PHP, Alpine, nginx or the bundled extensions get an update.

```bash
docker run -p 8080:80 -v "$PWD":/var/www/html ghcr.io/megathorx/nginx-php:8.5
```

Or as the base for your application:

```dockerfile
FROM ghcr.io/megathorx/nginx-php:8.5
COPY . /var/www/html
```

## What's inside

- nginx on port 80, serving `/var/www/html`, and PHP-FPM on a unix socket, both run by supervisord.
  Logs go to stdout/stderr.
- PHP extensions on top of the official image: `gd` (freetype, jpeg, webp), `imagick`, `redis`, `intl`, `mysqli`,
  `pdo_mysql`, `pdo_sqlite`, `exif`, `soap`, `xsl`, `zip`, `opcache`, `dom`.
- PHP settings: `memory_limit = 512M`, `upload_max_filesize` and `post_max_size` `100M`, `variables_order = "EGPCS"`,
  `cgi.fix_pathinfo = 0`, and `clear_env = no`, so environment variables reach PHP.
- nginx: `client_max_body_size 100m`, the real client IP from `X-Forwarded-For` for proxies in `172.16.0.0/12`,
  access to dotfiles denied. The site config is `/etc/nginx/sites-available/default.conf`.

## How the images stay up to date

A [GitHub Actions workflow](.github/workflows/build-image.yml) checks every supported PHP version daily at 03:17 UTC
and whenever the Dockerfile, configuration or build scripts change on `main`. A version is rebuilt when:

- it is a **new PHP version**: released, listed on [endoflife.date](https://endoflife.date/php) and published
  upstream as `php:<version>-fpm-alpine`,
- the upstream `php` image changed (a **PHP patch release** or an **Alpine update**),
- any installed **Alpine package**, nginx included, has an update,
- a new release of the **imagick or redis** extension is out, or
- the Dockerfile or configuration in this repository changed.

Each build is smoke-tested on both architectures before it is published: nginx has to serve PHP, all extensions have
to load and Imagick has to encode images. If a build fails, the previous image stays in place.

`latest` and the major tag (`8`) move to a new PHP version once its first image is published. Until then they stay
on the previous version, which keeps receiving updates.

When a PHP version reaches its **end of life** (end of security support), its images are no longer rebuilt. They stay
available and move to the "End of life" table above.

The workflow commits the image list to `main` itself. If `main` gets branch protection, allow GitHub Actions to push
to it, otherwise the list stops updating (the images are still built).

## Adding PHP extensions

The images contain no compilers or build tools. Install them temporarily in your own image:

```dockerfile
FROM ghcr.io/megathorx/nginx-php:8.5
RUN set -eux; \
    apk add --no-cache libpq; \
    apk add --no-cache --virtual .build-deps $PHPIZE_DEPS postgresql-dev; \
    docker-php-ext-install pdo_pgsql; \
    apk del .build-deps
```

`pecl` is not available from PHP 8.6 on. Build PECL extensions from their source tarball instead:

```dockerfile
FROM ghcr.io/megathorx/nginx-php:8.5
RUN set -eux; \
    apk add --no-cache --virtual .build-deps $PHPIZE_DEPS; \
    docker-php-source extract; \
    mkdir /usr/src/php/ext/apcu; \
    curl -fsSL https://pecl.php.net/get/apcu | tar -xz --strip-components=1 -C /usr/src/php/ext/apcu; \
    docker-php-ext-install apcu; \
    docker-php-source delete; \
    apk del .build-deps
```

## Building locally

```bash
docker build --build-arg PHP_VERSION=8.5 --build-arg IMAGICK_VERSION=3.8.1 --build-arg REDIS_VERSION=6.3.0 -t nginx-php:8.5 .
scripts/smoke-test.sh nginx-php:8.5 8.5
```

`python3 scripts/versions.py` shows which versions would be built and why, and
`python3 -m unittest discover -s scripts` runs the tests for the build scripts.
